# hxwl-07 航空维修检查清单

按 ATA 章节推进维修放行前检查，覆盖「检查项 → 缺陷 → 延期/关闭 → 放行签署」完整闭环。

## 技术栈

React 19 + Vite + TypeScript + CSS（localStorage 本地持久化）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5107

## 业务规则

### ATA 检查项与缺陷

- 每个 ATA 检查项（章节 / 区域 / 检查项目 / 责任工程师）下可登记多条缺陷
- 每条缺陷记录：**缺陷等级**（一般 / 重要 / 严重）、**整改期限**、**责任工程师**
- 缺陷可登记延期：逾期缺陷必须填写**延期依据**与延期后整改期限，延期链按顺序追加、不可改写
- 缺陷整改后填写关闭说明关闭；关闭后不再阻断签署

### 放行签署闭环

- 存在任何未关闭缺陷时**不得签署放行**，签署按钮锁定并逐条列出阻断缺陷
- 未关闭的逾期缺陷必须先填写延期依据（延期后新期限仍逾期的，继续拦截要求补依据）
- 全部缺陷关闭后才可签署 V1
- 签署后若又登记新缺陷，需再次全部关闭才能重新签署
- 重新签署**必须填写新版本原因**；原签署保留、不可修改或删除，新版本号递增，时间线展示每版原因/签署人/时间/台账快照

### 维修车辆机位占用仲裁

- 提交占用申请（车辆 / 机位 / 时段 / 关联检查项）后先进入「待确认」
- 确认时与该机位**已确认**（先确认）的记录做半开区间时段重叠判定
- 重叠：只保留先确认的一条，后提交的一条驳回，并列出**冲突机位、双方时段、先确认车辆、冲突检查项**
- 不重叠：确认成功，后续重叠申请将被其驳回

### 持久化

- 检查项、缺陷、延期依据、签署版本、机位占用（含驳回时的冲突快照）整体写入 localStorage
- 刷新页面后通过 ID 关联恢复，四类数据仍相互对应
- 页脚提供「重置为演示数据」

## 目录

```
src/types.ts    数据模型（检查项 / 缺陷 / 延期 / 签署版本 / 机位占用）
src/domain.ts   规则引擎（放行闸口、逾期判定、时段重叠、指标、演示数据）
src/store.ts     React store 与 localStorage 持久化
src/App.tsx     页面与交互
```
