# hxwl-07 航空维修检查清单

按 ATA 章节推进维修放行前检查，覆盖「检查项 — 缺陷闭环 — 放行签署 — 机位占用」完整业务闭环。

## 技术栈

React 19 + Vite + TypeScript + 原生 CSS，数据保存在浏览器 localStorage（键 `hxwl-07-maintenance-state-v1`）。

## 本地运行

```bash
npm install
npm run dev      # 开发
npm run build    # 类型检查通过后产物构建
```

开发端口：5107

## 业务规则实现

### ATA 检查项与缺陷

- 每个 ATA 检查项记录：机型/机号、ATA 章节、检查区域、检查项目、**责任工程师**。
- 检查项下可登记多条缺陷，每条记录**缺陷等级**（一般 / 重要 / MEL保留）、**整改期限**、描述、登记/关闭时间。
- 缺陷可关闭、可重新打开（用于演示关闭后再签署的场景）。

### 放行签署闭环

- 签署前闸门自动校验，**存在未关闭缺陷时不得签署放行**，清单逐项列出阻碍缺陷及其检查项与责任工程师。
- **逾期缺陷必须填写延期依据**（MEL 批复 / 器材调拨单 / 质量部门批准文件），未填写同样禁止签署。
- **关闭后再签只能保留原签署并生成带原因的新版本**：历史版本只读不可改，再次签署强制填写新版本生成原因。
- 每个版本保存签署时刻的状态快照（检查项数、未关闭/已关闭缺陷数、附延期依据数），后续数据变化不影响历史版本。

### 维修车辆机位占用

- 同一机位时段重叠时**只保留先确认的一条**（以确认时间为准）。
- 后提交直接驳回、不落库，冲突提示列出**机位、申报时段、先确认车辆、冲突检查项（ATA/项目/责任工程师）及确认时间**。
- 相邻时段（如 09:00–12:00 与 12:00–13:00）不算冲突。

### 刷新一致性

检查项、缺陷、签署版本、机位占用四类数据共用同一份持久化状态，占用通过检查项 ID 关联，刷新页面后仍完整对应；页面右上角可一键恢复演示数据。
